# 双机协作交接规范

更新日期：2026-10-16　状态：草案（待确认生效）
用途：定义 **编排端（Orchestrator，NAS）** 与 **执行端（Executor，PC）** 的职责边界、真相源约定与脚本归宿规则，补全"执行端脚本/临时代码的归档"这一缺口。
相关指针：《双机路由约定》（消息路由）｜《技术交底》（环境与未完成清单）｜《PC 直连契约》（调用链路）｜《接入论证》（防漂移五条）

> 分工边界：**消息路由** 归《双机路由约定》（§一 路由规则：默认指向编排端，显式点名则直通执行端；§四 旁路插件）；本文只规范 **文件/脚本归属与规则**。
> 检索键：`双机交接` `执行端`　→ `wk-find 执行端`

## 一、两个角色

| | 编排端（Orchestrator） | 执行端（Executor） |
|---|---|---|
| 位置 | 飞牛 NAS `<NAS_HOST>`（<NAS_IP>） | PC（Windows，DHCP 地址漂移；`state/pc_host.txt` 运行时解析） |
| 职责 | 跨机编排 / 通道 / 治理 / **共享真相源唯一写入者** | 本地执行：Windows 运维、嵌入式编译烧录、串口、本地文件 |
| 工作区 | `<OPENCLAW_PATH>`（**唯一长期事实源**） | 独立本地目录（**易变执行区**） |
| 记忆 | 自持 | 自持，**不自动互相同步** |

---

## 二、工作区关系（唯一真相源原则）

- NAS `workspace/` + `docs/` = **唯一长期事实源**；编排端 = 唯一写入者。
- 执行端对共享源**只读**，**不得**在本地另写"本地版 workspace 文档"（两份真相必然漂移）。
- 执行端的**发现/结论/踩坑** → 回报编排端，由编排端写入 NAS 文档。
- 稳定物理事实（机器角色/IP/硬件/固件包）→ NAS 共享；易变上下文（当前任务/会话）→ 各自 `MEMORY.md`；机密（token/口令）**只传位置，不传密文**。
- 认领任务先核版本：`sha256sum <OPENCLAW_PATH>`，哈希变化即重读。

## 三、执行端脚本 / 临时代码的归宿

**现状实测（2026-10-16）**：执行端工作区约 **5005 文件 / 462 目录 / 187MB**，大量一次性脚本与产物（`.py` 1555、`.pyc` 1295、`.sh` 407、`.png` 606、`.log` 100…），命名多为 `apply_*.sh`、`a16.py`、`audit1/2.sh` 类流水号。**NAS 侧零副本，未落盘。**

**归宿规则（草案，待定）**：

1. **一次性脚本 / 临时产物** → 留在执行端本地，不搬入 NAS（避免污染唯一真相源）。本地需**归目录 + 加注释头**：`scripts/`（脚本）｜`tmp/`（临时）｜`logs/`（日志）｜`assets/`（截图/固件包）。
2. **有复用价值的脚本 / 命令** → 回报编排端，由编排端**上提为共享资产**（NAS `/usr/local/bin` 脚本或 `wk.sh` 函数），**登记台账 + 打检索词**。判据：同一逻辑重复 ≥3 处，或属"出口/取数型"能力（参见《架构设计与复用体系》§D2）。
3. **结论 / 事实 / 踩坑** → 回报编排端写入 NAS `docs/`（踩坑进《踩坑总表》、经验进《经验库》）。
4. **命名**：禁止 `a16.py`、`audit1.sh` 类流水号；使用**语义名**。
5. **定期清理**：`.pyc` / 过期日志 / 一次性截图不囤积（执行端自理，参照 NAS《清理策略总表》原则）。

> 原则：**执行端是操作台，自由使用；有复用价值的产出，回报编排端上提至 NAS。**

### 实测补充（2026-10-16，编排端 SSH 只读清点）

执行端已做归档，但未按规则执行，且已出现漂移：

- **有分主题目录**：按主题分了若干个 `_` 前缀目录（包解构、镜像副本、参考资料、包补丁、草稿、快照等）。
- **散件为流水号**：`_c1..N.sh`、`_mkinit1..N.sh`、`_crop1..N.py` 这类纯序号命名，不符合命名规范。
- **⚠️ 漂移（违反防漂移 §5.1）**：执行端存在编排端文档的多版本副本——同一份《踩坑总表》存在 `_bak`、`_bak2/3/4` 多个版本，另有规则脚本副本与文档树副本。**此为「同一事实两份真相」的典型根因**。
- **错误记录缺失**：执行端仅有过程日志，**无统一错误/经验库**；本地错误未回报编排端，无法沉淀。

## 四、行为规则（执行端适用）

**红线**：不外传敏感信息；不将 NAS 机密落盘到 PC；公网不暴露服务；不 root 直登；不终止系统原生应用；**不在聊天/命令行写入备份口令**。
**输出**：统一简体中文；只给结果，不复述、不赘述；一次办结；不可行直说；失败必上报、不吞错；改动前先备份（`.bak.YYYYMMDD-HHMMSS`）。
**成本控制／反死循环**：索引命中后**用本地命令（grep/head）读片段**，禁止将整文件/整仓/整页塞入上下文；同一手段连续失败或无进展 **≥2~3 次即停**，先列出「绕过／跳过／替代」候选（≥2 个）再选；**禁止无脑重复**；卡住必须上报。
**交付归属**：每次交付显式声明来源角色，如 `【执行：Executor(PC)｜编排：Orchestrator(NAS)】`。
**分歧处理**：以原始证据（源码/串口日志/实测）为准，禁止 Agent 间互相说服；一处修改（NAS docs）后另一侧重新读取。
