# 规范 · 文档

> 归属：5+1 类资产之"文档"
> 状态：建议执行
> 目的：文档是"单一真相源"——只留一份准的、一眼能看出新旧、随时找得到入口。

## 一、为什么要有这条

长期维护最大的敌人是"文档版本地狱"：同一件事有三个版本散在三处，改完忘了同步，最后没人知道哪份算数。文档一乱，等于没有文档——还会误导自己，甚至照着过期说明操作。

所以规则是：**唯一位置、统一状态头、统一索引、旧版归档**。让"哪份准"这件事永远只有一种答案。

## 二、规范内容

| 维度 | 规则 |
|---|---|
| 位置 | 集中于一个文档目录（单一真相源） |
| 命名 | 中文自解释名；历史件带日期 `名称-YYYY-MM-DD.md`；**禁止**"任务三"这类临时代号 |
| 状态头 | 每篇首部必须有：标题 + **更新日期** + **状态**（草案/生效/已执行/待执行…），可选"来源" |
| 归档 | 旧版/过期移入 `archive/`，文件名保留日期，**不删除** |
| 索引 | 维护一个 `README` 清单：文档名 / 用途 / 状态 |
| 指针 | 长期记忆里**只放指针**（某主题 → 某文档），不复制正文 |
| 变更 | 正文"更新日期"随改随更；结构性旧版进 `archive/` |
| 红线 | 不把高频变动的日志/状态塞进文档；不在文档里写密钥（见《规范 · 脱敏》） |

## 三、怎么落地

1. 定一个文档目录 + 一个 `archive/` 子目录。
2. 新文档模板：第一行标题、第二行更新日期、第三行状态。
3. 每建 / 改 / 归档一篇，**同步更新 README 索引**。
4. 旧版移 `archive/`，而不是覆盖。
5. 记忆文件只写指针。

## 四、怎么改（按你的情况）

- **文档很少（<10 篇）** → 索引可省，但**状态头必须**。
- **文档很多** → 除总索引外可加分类索引；状态词统一。
- **多人协作** → 增加"负责人"字段。
- **文档要对外** → 先过《规范 · 脱敏》。
- **临时笔记** → 放草稿区，别混进真相源。

## 五、检查（巡检项）

- [ ] 每篇都有标题 + 状态头
- [ ] 每篇都在 README 索引里登记（**漏登记即告警**）
- [ ] 过期文档已移入 `archive/`
- [ ] 无临时命名（"任务N"类）
- [ ] 记忆文件只含指针、未堆正文
- [ ] 文档里无明文密钥 / 真实隐私
