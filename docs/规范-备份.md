# 规范 · 备份

> 归属：5+1 类资产之"备份"
> 状态：必须执行
> 目的：没有备份就没有回滚；而备份本身也要有秩序，否则该有的没有、该删的堆积。

## 一、为什么要有这条

改配置、升级、迁移——任何一步出错，唯一的救命绳就是备份。现实里却常见两种反向翻车：

一是**该备份的没备**，出事只能从头再来；二是**备份自己乱掉**——混放、命名随意、无限堆积、占满磁盘，甚至把密钥一起备了出去。

所以备份的关键从来不是"备没备"，而是**备在哪、怎么命名、留几份、记没记、能不能还原**。

## 二、规范内容

| 维度 | 规则 |
|---|---|
| 归口 | 脚本自动备份 → `<备份根>/<服务>/`；手工备份 → `<工作区>/backup/`。两者**分开**，脚本产物不得混进手工目录 |
| 命名 | 手工：`文件名.bak.YYYYMMDD-HHMMSS`（同日多份用时间区分，**不用** `.bak.1/.bak.2` 序号） |
| 保留 | 按服务设**硬上限**（例：核心快照 30 份、设备数据 4 份、摄像头图/视频 7 天、会话存档 90 天） |
| 台账 | 每次重要操作记一行：时间 / 文件 / 原因 / **恢复命令** |
| 回收 | 过期备份进 `trash/`，保留 30 天，不直接 `rm` |
| 大小 | 手工备份目录设总大小软上限（如 512MB），超限触发整理 |
| 红线 | 禁止规范外的第二备份目录；备份里**不得**含明文密钥 |

> 上表数值为 **示例默认（来自实战）**，是长期运行调出来的实际值，非理论建议；照抄可用，也可按第四节调整。

## 三、怎么落地

1. 定两个目录：脚本产物目录 + 手工备份目录，写进规范。
2. 所有改动前 `cp 文件 文件.bak.$(date +%Y%m%d-%H%M%S)`。
3. 核心配置每日定时**全量快照**，超份数删最旧。
4. 台账文件连续追加，**每条必须带恢复命令**——没有恢复命令的记录等于没记。
5. 过期/废弃备份统一走 `trash/`。

## 四、怎么改（按你的情况）

- **只有一个人维护** → 保留份数可少（如核心 7 份），但**恢复命令**必须写。
- **多服务** → 每服务独立子目录，份数按重要性分级（核心多、临时少）。
- **磁盘小（<100G）** → 份数减半 + 压缩备份；定期把冷备份搬走。
- **合规/审计要求** → 关掉自动删，改"归档到冷存储 + 只读"。
- **备份含密钥** → 必须加密或排除，见《规范 · 脱敏》。

## 五、检查（巡检项）

- [ ] 手工备份目录总大小未超软上限
- [ ] 核心快照份数未超硬上限
- [ ] 台账最后修改时间在合理范围内（说明还在记）
- [ ] 没有出现规范外的第二备份目录
- [ ] 抽查：随机一条台账记录能**照恢复命令还原**
- [ ] 备份内容里没有明文密钥
