# 规范 · 脱敏

> 归属：跨类红线（开源 / 外发的"命门"）
> 状态：必须执行
> 目的：任何对外发布（代码仓库、截图、文档、日志）的东西，都必须先过脱敏——一次疏忽 = 永久泄露。

## 一、为什么要有这条

一旦把带真实信息的内容推到公开仓库或发给别人，**泄露是永久的**：删掉提交、删掉仓库，别人 clone / fork / 缓存的副本都还在。

密钥、内网 IP、域名、路径、私人数据——任何一样漏出去，都可能被用来入侵、探测、骚扰、撞库。更麻烦的是"半泄露"：你只删了正文，历史提交里还在。

所以对外动作**之前**必须脱敏，而不是出事之后再补救。

## 二、规范内容

### 2.1 必须脱敏 → 占位符

| 类别 | 替换为 |
|---|---|
| 账号 / 密码 / 令牌 / API Key | `<TOKEN>` `<PASSWORD>` `<API_KEY>` |
| 内网 IP / 公网 IP | `<内网IP>` `<公网IP>` |
| 真实域名 / 子域名 | `<你的域名>` |
| 主机名 / 容器名 | `<主机名>` |
| 私有绝对路径 | `<工作区>` `<HOME>` `<备份根>` |
| 个人 / 联系人信息、聊天记录、截图 | 删除或打码 |
| 私钥文件（`*.pem` `*.p12` `id_rsa` …） | **绝不提交**，加入忽略规则 |

### 2.2 通用规则

- 配置类文件、`.env`、部署文件（compose / Dockerfile / nginx 配置）、含凭据的脚本，一律**不进公开仓库**。
- 只 `git add` 明确列出的文件，**禁止 `git add -A` / `-f`**。
- 推送前跑一次**密钥扫描**。
- 脚本里的真实路径 / 域名 / 凭据一律**参数化**（读环境变量或本地配置）。

## 三、怎么落地

1. 建一份"否定清单"写进 `.gitignore` / `.git/info/exclude`：`*.env`、`*secret*`、`*token*`、`*.key`、`*.pem`、部署文件、`node_modules`。
2. 占位符规范化（见 2.1），全仓库统一用**同一套**。
3. 推送前**逐个文件**暂存，跑密钥扫描：正则扫 `sk_`、`ghp_`、`AKIA`、`BEGIN .* PRIVATE KEY`、长随机串、内网 IP 段。
4. 示例配置只留占位符（`config.example`），真实值本地填。
5. 万一泄露：**立刻撤销 / 轮换**该凭证——撤销永远比删除有效。

## 四、怎么改（按你的情况）

- **纯本地私有仓库** → 可放宽，但**密钥仍禁止入库**（仓库可能被误设公开）。
- **要开源分享** → 全面占位符 + 脚本参数化 + 提供 `*.example` 配置。
- **要放截图/演示** → 聊天记录、头像、备注、余额、订单号都要打码。
- **团队协作** → 用密钥管理（环境变量 / 密管服务），配置文件只放键名不放值。
- **疑似已泄露** → 按**最坏情况**处理：先撤销，再评估。

## 五、检查（巡检项）

- [ ] 忽略规则覆盖所有密钥 / 配置 / 部署类文件
- [ ] 待推送文件里无真实 IP / 域名 / 路径 / 凭证（密钥扫描）
- [ ] 脚本无硬编码凭据（抽查）
- [ ] 示例配置只含占位符
- [ ] 已泄露凭证是否已撤销 / 轮换
- [ ] git 历史中无历史遗留的密钥（必要时重写历史）
