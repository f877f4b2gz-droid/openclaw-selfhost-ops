# 规范 · 技能

> 归属：5+1 类资产之"技能"
> 状态：建议执行
> 目的：装了什么、什么版本、改过什么，都要说得清、可停用、可追溯。

## 一、为什么要有这条

助手的能力一半来自"技能 / 插件"。装多了常见三个问题：**不知道装了什么**、**升级把本地改动冲没**、**停用靠手删难回退**。

没有版本和变更记录，出了问题根本没法判断"是某个技能搞的，还是那次升级搞的"。所以要强制**版本 + 变更记录 + 清单**三件套。

## 二、规范内容

| 维度 | 规则 |
|---|---|
| 位置 | 技能集中在一个技能目录，目录名 = 技能 id（小写连字符） |
| 版本 | 每个自建技能必须有 `VERSION`（版本号） |
| 变更 | 每个自建技能必须有 `CHANGELOG.md`（按版本追加） |
| 清单 | 维护"技能清单"：名称 / 类型 / 状态 / 用途 |
| 停用 | 停用技能移入 `_disabled/`（保留，不删） |
| 来源 | 自建与第三方（git / 市场装）分开标注，第三方不强制自管版本 |
| 升级 | 主程序升级后，**重跑**受影响的自建技能补丁 / 检查 |
| 红线 | 不在技能里写密钥；技能对外分享前先脱敏 |

## 三、怎么落地

1. 自建技能模板：`SKILL.md` + `VERSION` + `CHANGELOG.md`。
2. 每次改动追加 CHANGELOG、更新 VERSION。
3. 新装 / 删除技能，**同步更新清单**。
4. 升级主程序后，重跑受影响的自建技能补丁（例：本地化补丁）。
5. 停用走 `_disabled/`。

## 四、怎么改（按你的情况）

- **技能少** → 清单可合并进主 README，但 VERSION / CHANGELOG 保留。
- **依赖第三方技能多** → 只对"自建"强制版本；第三方记来源与 commit。
- **要发布技能** → 补 LICENSE + README + 示例，先过《规范 · 脱敏》。
- **频繁升级主程序** → 建"升级后必跑"清单（补丁 / 检查脚本）。
- **技能冲突** → 停用进 `_disabled/`，别删除，方便回退。

## 五、检查（巡检项）

- [ ] 自建技能都有 `VERSION`（缺 VERSION 即告警）
- [ ] 自建技能都有 `CHANGELOG.md`
- [ ] 技能清单与实际目录**一致**
- [ ] 停用技能在 `_disabled/` 内（未误删）
- [ ] 升级后补丁 / 检查已重跑
- [ ] 技能内无明文密钥
