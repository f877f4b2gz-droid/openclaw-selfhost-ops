# 规范 · 记忆

> 归属：5+1 类资产之"记忆"
> 状态：可选
> 目的：记忆要**长期可查**，但不能**无限膨胀**——膨胀的记忆既烧 token，又让重点变模糊。

## 一、为什么要有这条

助手的记忆分两种：**长期**（跨会话要记住的）和**每日**（当天工作日志）。两个极端都会出问题：

一是把什么都堆进长期记忆，越读越厚，每次对话都在烧 token、还稀释了重点；二是随手乱丢，需要时找不到。

正解是：**长期只留指针 / 红线，日常进日记，超期归档**——让"该记的记得住、不该占的不占"。

## 二、规范内容

| 维度 | 规则 |
|---|---|
| 长期 | `MEMORY.md`：只放**索引 / 红线 / 指针**，不堆正文 |
| 日记 | `memory/YYYY-MM-DD.md`，按天追加 |
| 保留 | 日记保留 **30 天** |
| 归档 | 超 30 天日记移入 `memory/archive/`（保留，不删） |
| 正文 | 详细内容落**文档**，记忆里只写"某主题 → 某文档" |
| 上下文 | 高频变动的文件（日志 / 状态）**不进上下文**，避免每轮都喂 |
| 红线 | 记忆里不写明文密钥（见《规范 · 脱敏》） |

> 上表数值为 **示例默认（来自实战）**，是长期运行调出来的实际值，非理论建议；照抄可用，也可按第四节调整。

## 三、怎么落地

1. 长期记忆保持"瘦"：能一句话指针就别抄整段。
2. 当天的事写进当天日记文件。
3. 加一个定时任务：超 30 天日记自动移 `archive/`。
4. 需要"记住"的结论落**文档**，记忆里补一条指针。
5. 检查上下文注入清单：只留固定小文件，日志类外置。

## 四、怎么改（按你的情况）

- **记性要求高** → 日记保留可延长（60/90 天），长期记忆仍只放指针。
- **Token 敏感** → 长期记忆进一步压缩，指针能指向就行。
- **多主题并行** → 日记可按项目分文件，但归档规则一致。
- **要审计** → 日记不删只归档，冷存留档。
- **隐私敏感** → 敏感内容不进记忆，或加密隔离保存。

## 五、检查（巡检项）

- [ ] 超过保留期的日记已归档
- [ ] 长期记忆**无正文堆砌**（只有指针 / 红线 / 索引）
- [ ] 记忆里**无明文密钥**
- [ ] 高频文件未进入上下文注入清单
- [ ] 指针指向的文档都存在
- [ ] `memory/archive/` 存在且在正常接收过期日记
