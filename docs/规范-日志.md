# 规范 · 日志

> 归属：5+1 类资产之"日志"
> 状态：必须执行
> 目的：日志无限增长会悄悄吃满磁盘，必须设上限。

## 一、为什么要有这条

自托管服务（缓存追踪、应用日志、容器日志）默认**没有上限**，
时间一长会从几百 MB 涨到几 GB，占满磁盘、拖慢系统，
而且**没有任何提醒**——等你发现时磁盘已经满了。

所以日志必须有：**大小上限 + 轮转 + 过期清理**。

## 二、规范内容

| 日志类型 | 上限 | 超限动作 | 保留 |
|---|---|---|---|
| 缓存追踪（cache-trace） | 300MB | 截断，保留最近 20% | 3 天 |
| 应用服务日志 | 50MB | 截断 | 7 天 |
| 容器日志 | 100MB | docker 自动轮转 | 5 个文件 |
| 轮转件 | — | 按天数清理 | 14/30 天分级 |

> 上表数值为 **示例默认（来自实战）**，是长期运行调出来的实际值，非理论建议；照抄可用，也可按第四节调整。

## 三、怎么落地

1. 缓存追踪：用 cron 每天检查一次，超 300MB 就截断保留最近 20%
2. 服务日志：logrotate 配置，超 50MB 轮转
3. 容器日志：daemon.json 设 `max-size: 100m`、`max-file: 5`
4. 轮转件：按 7/14/30 天分级清理

## 四、怎么改（按你的情况）

- **磁盘小（<100G）** → 上限减半（缓存追踪 150MB、服务日志 25MB）
- **磁盘大（>1T）** → 上限翻倍，保留时间延长
- **要长期留存审计** → 别截断，改成"归档到冷存储"
- **不在乎日志** → 至少给个硬上限（防爆盘），其余随意

## 五、检查（巡检项）

每周跑一次巡检，确认：
- [ ] 缓存追踪文件不超过上限
- [ ] 没有日志文件超 1GB
- [ ] 轮转件按规则在清理
