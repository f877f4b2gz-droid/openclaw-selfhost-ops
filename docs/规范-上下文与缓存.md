# 规范 · 上下文与缓存

> 归属：跨类机制（上下文 / 缓存）
> 状态：建议执行
> 目的：把"不烧上下文、不烧 token"从口号变成规则——分清哪些改动安全、哪些会打断缓存、什么该外置、什么该拉长间隔。

## 一、为什么要有这条

长期运行里最贵的两样东西，是**上下文**和**缓存**：

- 每一轮对话，都要把固定文件（人格、规则、记忆、工具说明）重新喂给模型——这部分越大，每轮越贵。
- 模型侧的**前缀缓存**能免掉重复计算，但只要前缀内容变了一个字，缓存就失效、整段重算——又慢又贵。

麻烦在于：这两类东西混在一起，很容易踩坑。随手改一句系统提示，缓存全废；该外置的日志却塞进记忆，每轮都在烧 token。

所以必须先把**两类东西分开看**：

| 类别 | 是什么 | 举例 | 改动影响 |
|---|---|---|---|
| **机制参数** | 行为旋钮 | 心跳间隔、压缩阈值、超时 | 不改提示词，**不动缓存**，随便调 |
| **提示词类** | 缓存前缀 | SOUL / AGENTS / MEMORY / 系统提示 / 工具说明 | 改一个字 = **缓存重建**，慎改、批量改 |

一句话：**机制参数随便调，提示词类慎改、批量改。**

## 二、规范内容

| 维度 | 规则 |
|---|---|
| 分类 | 先分"机制参数"与"提示词类"；前者随意，后者慎改 |
| 提示词改动 | 能批就批、能一次改完别分多次；改一次 = 缓存重建一次 |
| 固定文件 | 进上下文的只放**固定小文件**（人格/规则/指针），求"小而稳" |
| 高频变动 | 日志 / 状态 / 会话等高变动内容**外置**，不进上下文 |
| 心跳 / 定时 | 跑在主会话 = 每轮带全量上下文；间隔越短越贵 |
| 压缩（compact） | 会断缓存，但是**一次性**；别频繁压、别反复手动压 |
| 红线 | 别把大段日志/数据塞进记忆或提示词；别把密钥写进提示词 |

> 上表数值为 **示例默认（来自实战）**，是长期运行调出来的实际做法，非理论建议；可按第四节调整。

## 三、怎么落地

1. **心跳拉长**：把 heartbeat 间隔设长（示例：**59 分钟**），比"最长的一次任务"略长即可——少跑几轮全量上下文。
2. **开缓存长保留**：`cacheRetention: long`，让前缀缓存更久有效；配合上面的长心跳，保持缓存"热"。
3. **开上下文裁剪**：`contextPruning` 裁掉陈旧消息，降低每轮体积（按需开）。
4. **提示词改动集中做**：SOUL / AGENTS / MEMORY 的改动攒到一起、一次改完，改完别再频繁动。
5. **固定文件瘦身**：工作区根目录只留固定小文件；`MEMORY.md` 只放指针，不放正文。
6. **高变动外置**：日志、状态、会话文件放到工作区**之外**，并把它们排除出"上下文注入清单"。

## 四、怎么改（按你的情况）

- **Token 敏感** → 心跳再拉长、裁剪开、固定文件进一步瘦身。
- **追求低延迟** → 缓存保留长一点、主模型尽量别换、别频繁改提示词。
- **迭代频繁（常改人格/规则）** → 集中在同一时间改，减少缓存重建次数。
- **磁盘/内存小** → 别把历史全留着，善用裁剪与归档。
- **多模型切换** → 换模型本身也可能断缓存，尽量固定主模型。

## 五、检查（巡检项）

每周跑一次巡检，确认：

- [ ] 进上下文的固定文件保持"小而稳"（无大段日志/数据）
- [ ] `MEMORY.md` 只有指针 / 红线，不是正文
- [ ] 高频变动文件未进上下文注入清单
- [ ] 心跳 / 定时任务间隔合理（未过密）
- [ ] 提示词类文件近期无频繁零散改动
- [ ] 上下文 / 提示词里无明文密钥
