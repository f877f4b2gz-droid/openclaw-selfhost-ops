# 信息资产管理规范

更新日期：2026-10-13（2026-10-15 补充总纲与第⑤项）
适用环境：飞牛 fnOS（<DOMAIN> / 本机 <HOST>）
体检脚本：`workspace/scripts/asset-audit.sh`（每周日 06:00，cron `/etc/cron.d/asset-audit`）

> 核心原则：每一类资产必须具备 **唯一位置 + 命名规则 + 保留/归档策略 + 变更记录 + 检索键**，缺一即视为不规范。

---

## 0. 总纲：按字典体例管理资产

**设计隐喻**（2026-10-13 提出，2026-10-15 补录）：参照《新华字典》的分层索引体例组织全部资产。

新华字典的六条体例 → 资产体系的对应：

| 字典体例 | 资产体系 |
|---|---|
| **字头唯一**：一个字只立一条目 | 每项资产只有一个权威定义处，禁止第二份正文 |
| **检字表**：拼音／部首／笔画／四角号码 | **同一批资产提供多条检索路径** → `wk-find <词>` 跨类直查 |
| **体例统一**：读音·释义·例证 固定结构 | 每类资产字段固定（位置／命名／保留／变更） |
| **分级**：常用字／次常用字／生僻字 | 资产分级：常驻／归档／冷存 |
| **交叉引用**：见 X 页／同 X | 资产之间只给指针，禁止复制 |
| **释义不重复** | 同一信息只解释一次，其余给指针 |

> ⚠️ **历史教训**：该隐喻在 2026-10-13 首次落盘时被误窄化为一种压缩技术——
> 仅落入 `docs/自备份设计.md` §6（RAPTOR 摘要树／restic／zstd），
> **丢失了「资产组织模型」这一半**。此后复查资产体系，均以本节总纲为准。

### 0.1 每类资产的五个必备项

| 项 | 要求 |
|---|---|
| ① 唯一位置 | 单一真相源，禁止第二处正文 |
| ② 命名规则 | 语义自解释；带日期的历史件 `名称-YYYY-MM-DD.md` |
| ③ 保留／归档策略 | 明确硬上限与去向（trash／archive） |
| ④ 变更记录 | 台账／CHANGELOG／更新日期 |
| ⑤ **检索键** | 必须可被 `wk-find` 命中：有明确的**字头 + 一句话**；**只给指针，不给副本** |

**第 ⑤ 项为补订条款**：规范首版（2026-10-13）仅含前四项，导致「知道有这东西」与
「找得到这东西」脱节——前者依赖人工记忆，后者依赖通读。检字表将后者变为一次查询。

工具 `wk-find`：总目／跨类检索／限定类。数据源登记在脚本内 `SOURCES` 表，
**只读现有权威文件，不建索引副本** → 零漂移。

## 1. 文档（docs/）

- **位置**：`workspace/docs/`（单一真相源）。
- **命名**：语义自解释名；带日期的历史件 `名称-YYYY-MM-DD.md`。**禁止**临时代号（如「任务三」）。
- **状态头**：每篇首部必须包含——`# 标题` + `更新日期：` + `状态：`（如 已执行/待执行/草案）。可选 `来源：`。
- **归档规则**：旧版本/过期文档移入 `docs/archive/`，文件名保留日期；不删除。
- **变更记录方式**：正文内「更新日期」随改随更；结构性旧版进 `archive/`。
- **索引**：`docs/README.md` 维护全部文档清单（名称/用途/状态）。
- **MEMORY.md 只做指针**：不复制正文，只写「某主题 → docs/xxx.md」。

## 2. 备份（backup/、<DATA_ROOT>/backup/）

- **位置**：
  - 脚本自动备份 → `<DATA_ROOT>/backup/<服务>/`（如 core、kavita、smartstrm-lists）。
  - 手工/改文件备份 → `workspace/backup/`。
  - **两者分开归口**，脚本产物不得混入 `workspace/backup/`。
- **命名**：手工 `文件名.bak.YYYYMMDD-HHMMSS`（同日可多份）；脚本产物按各脚本约定。
- **保留策略**（硬上限）：
  - `core` 最新 1 份；`lan-watch` 4 份；海康/大华侦测图与夜间视频 7 天；<User_B> 会话存档 90 天。
  - `workspace/backup/` 总大小软上限 **512MB**，超限触发整理。
- **归档规则**：过期备份进回收 `trash`（见附录），不直接 rm。
- **变更记录方式**：`workspace/backup/台账.md` **连续记录**，每条 = 时间 / 文件 / 原因 / 恢复命令。仅记录重要操作（改配置、改角色设定、规范落盘）。
- **禁止**：规范外的第二备份目录（历史上曾出现 `workspace/backups/`）。

## 3. 配置（openclaw.json、/etc/cron.d/、/usr/local/bin/*.sh）

- **位置**：`~/.openclaw/openclaw.json`；`/etc/cron.d/`；`/usr/local/bin/`。
- **命名**：改动前备份 `文件名.bak.YYYYMMDD-HHMMSS`（统一时间戳式，不用 `.bak.1/.bak.2` 序号）。
- **保留策略**：同文件保留最近若干份（openclaw.json 保留最近约 10 份）；`.last-good` 常驻。
- **归档规则**：过期 `.bak` 转 `trash`。
- **变更记录方式**：
  - 配置改动写入 `workspace/backup/台账.md`（时间/文件/原因/恢复命令）。
  - **定期快照**：`core-backup.sh` 每日 04:30 执行；core 同盘包只留**最新 1 份**，跨盘每日快照保留 30 份。
- **红线**：改任何脚本前先 `.bak`；不以 sudo 直改属主文件。

## 4. 技能（skills/）

- **位置**：`workspace/skills/<name>/`。
- **命名**：目录名 = 技能 id，小写连字符。
- **状态**：每个技能应有 `VERSION`（版本号）+ `CHANGELOG.md`（变更记录）。
- **保留策略**：可用技能常驻。
- **归档规则**：停用技能移入 `skills/_disabled/`（保留，不删）；未识别/半停用技能同样归此。
- **变更记录方式**：`CHANGELOG.md` 按版本追加；`VERSION` 随改随更。
- **清单**：`docs/技能与插件清单.md` 记录名称/类型/状态/用途。

## 5. 记忆（MEMORY.md、memory/）

- **位置**：`MEMORY.md`（长期）；`memory/YYYY-MM-DD.md`（日记）；`memory/archive/`（归档）。
- **命名**：日记 `YYYY-MM-DD.md`。
- **保留策略**：日记保留 **30 天**，超期归档。
- **归档规则**：超 30 天的日记移入 `memory/archive/`（保留，不删）。
- **变更记录方式**：日记按天追加；MEMORY.md **只放索引 / 红线 / 指针**，不堆正文。
- **其它**：`DREAMS.md` / `memory/.dreams/` 为独立的会话复盘机制，与日记分离。

## 6. 日志与附件（cache-trace.jsonl、openclaw.log、各服务日志、media/ 附件）

### 全机日志分层（职责划分，截至 2026-10-14）
| 层 | 日志 | 轮转归属 | 策略 |
|---|---|---|---|
| 应用（OpenClaw） | `cache-trace.jsonl`；`/tmp/openclaw/openclaw-*.log` | `log-rotate.sh` | 超300M重写；gzip + 14天删 |
| 系统 | `syslog/auth/kern/cron/mail/user.log` | fnOS logrotate(rsyslog) | 每日/50M/留7/压缩 |
| 应用中心 | `/var/log/apps/*.log`（trim.media/security 等） | fnOS logrotate(app-center) | 每日/留7/压缩 |
| 服务 | `samba` | logrotate(samba) | 系统自带 |
| **fnOS 自有组件** | `trim_app_center/trim_sac/trim-connect/trim_open_gateway/trim_license/cloud_storage_dav/updatemgr` | **新增 `/etc/logrotate.d/trim-local`** | 每日/size 20M/留7/压缩(copytruncate) |
| 容器 | Docker 容器日志 | Docker 自带 | `max-size 100m × max-file 5` |
| 系统 | `journald` | systemd-journald | **`SystemMaxUse=200M`**（2026-10-14 加入） |

- **体检**：`nas-daily-check.sh`（每日 09:00）输出「日志体检」：`/var/log` 总量、journald 用量、**报错日志列表（近800行错误计数）**、大日志 Top3 → 经 `qq-send.sh` 推送通知。
- **原则**：系统自带轮转**不改动**，只补缺口（trim-local）+ 设上限（journald）+ 巡检。

- **位置**：`~/.openclaw/logs/cache-trace.jsonl`；`/tmp/openclaw/openclaw-YYYY-MM-DD.log`；`/var/log/*.log`。
- **命名**：主日志按日切分（框架自管）；服务日志按服务名。
- **轮转 + 大小上限**（统一登记于此）：
  - `cache-trace.jsonl`：超 **300MB** 原地重写，只保留最近 **20% 行**（`log-rotate.sh`，每日 04:10）。稳态约 170–300MB。
  - 主日志：按天自动滚（`/tmp/openclaw/openclaw-*.log`）。
  - 服务日志（`lan-watch.log`/`cam-watch.log`/`nas-daily-check.log`）：超 **50MB** 截断留最近 1000 行；历史轮转件按 14/7/30 天清理（`log-rotate.sh`）。
  - `log-rotate.sh` 输出重定向 `>> /var/log/log-rotate.log`（可查执行记录）。
- **归档规则**：过期轮转件按上述天数删除；不保留无限历史。
- **变更记录方式**：`/var/log/log-rotate.log` 每次执行落一行。

### 附件 / 媒体（`~/.openclaw/media/`）
- **位置**：`media/qqbot/downloads/`（语音/附件入站）、`media/outbound/`（系统生成的语音/图片）、`media/inbound/`（入站附件）。
- **保留策略**：语音（`downloads/*.wav|mp3`）**转文字后即删**——随每日轮转清理（保留 60 分钟缓冲防误删，`MEDIA_VOICE_MIN`），不长期留存（转写文本已进会话记录）；其他附件（outbound/inbound、外部推送副本）保留 **7 天**（`MEDIA_CLEAN_DAYS`）。
- **推送副本**：脚本用 `openclaw message send --media` 发图/视频时，网关会**自动在 `media/` 留一份副本**——此为发送暂存，**权威目录仍是各自原目录**。这些副本同样按 7 天清理。**建议**：能以链接推送即不使用 `--media`，从源头减少副本。
- **执行**：并入 `log-rotate.sh` §6（**不新开任务**）；随 `/etc/cron.d/lan-maintenance` **每日 04:10** 执行（含日志压缩 §7）；日志见 `/var/log/log-rotate.log`。
- **临时文件**：workspace 根目录 `tmp_*.py|sh`、`*_build.log`，以及 `/tmp` 下同属主临时脚本，统一按 7 天清理。

### 日志压缩（忙/闲自适应）
- `log-rotate.sh` §7：**近 24h 有活动会话 → 每天**压缩归档；**低活动 → 隔约 3 天**（`/var/lib/log-rotate.last-logclean` 记录上次）。
- 做法：`gzip` 非当日 `/tmp/openclaw/openclaw-*.log`；`*.log.gz` 超 **14 天**删除。

## 7. 日志报错知识库（Runbook）

- **位置**：`workspace/knowledge/log-errors/`（`kb.jsonl` 知识库 / `pending.tsv` 待研究 / `README.md` 规范）。
- **目的**：同一报错只研究一次；命中即免联网（降低重复分析成本，结论持久化）。
- **指纹**：`log-fingerprint.sh` 对报错行归一化（时间/路径/PID/数字/hex）并**脱敏**（token/JWT/长 blob → `<REDACTED>/<JWT>/<BLOB>`）后取 10 位短哈希。
- **分级**：`known-harmless`（忽略降噪）/ `known-manual`（每日列出待人工处理）/ `new`（待研究）。
- **流程**：每日巡检指纹比对 → 新指纹进 `pending.tsv` 并播报 → 研究（联网仅一次）→ 结论写 `kb.jsonl`（带 `ref`+`conf`）→ 再现命中免查。
- **字段**：见 `knowledge/log-errors/README.md`（含 `review` 复核日期，默认 +180 天）。
- **红线**：**只诊断，不处置**；任何自动动作均不修改系统。
- **工具**：`/usr/local/bin/log-fingerprint.sh`、`/usr/local/bin/log-error-kb.sh`。

## 8. 项目（projects/）

- **位置**：`workspace/projects/<项目id>/`（id 小写连字符，如 `gameseed`、`my-agent`）。
- **每个项目固定文件**：`README.md`（交接文档·唯一入口）、`PROTOCOL.md`（协议/契约，**有则平级置于项目根，不放 `design/`；契约非草案**）、`STATUS.md`（滚动当前状态）、`decisions.md`（决策记录，只增）、`CHANGELOG.md`（变更日志，只增）；可选 `design/`、`assets/`、`archive/`。
- **状态头**：`README` / `STATUS` 首部含 `更新日期` / `状态`。
- **更新规则**：**`STATUS` 覆盖更新前，先将上一版要点压入 `CHANGELOG`**（保证可追溯，禁止无声覆盖）；`decisions` / `CHANGELOG` 只追加、不改写。
- **冲突处理**：执行过程与文档不一致时，以需求方最新明确指令为准，在 STATUS/CHANGELOG 记录冲突项并主动提示。
- **索引**：`projects/README.md` 维护项目清单。
- **详规**：《项目区规范》（`docs/项目区规范.md`）；工具：技能 `project-keeper`。
