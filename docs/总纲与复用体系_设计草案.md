## 一、主人原始诉求（3 条语音，原意归纳）

1. **要一个总纲**：文档/脚本/项目/杂项太多，需要一个顶层记录「我们做过哪些项目、用过哪些东西」。
2. **总纲要覆盖"所有操作容器/能力"，不只最近项目**：从总纲找到某个能力（如"要调用 X"）→ 进下一级 → 选中它 → 看「用它做过什么 / 通过什么方式成功过 / 复用哪些脚本与命令 / 踩过哪些坑（别再犯）」。**成功经验存起来**。
3. **高频复用要上提到上一层**：像 QQ 通知窗口那样——"所有东西都调这一个窗口，别各自重复造轮子"。常用的代码/脚本要**目录归纳 + 加注释**，用时直接调用。并探讨：**调用 vs 重写**。

> 主人明确：不一定照搬他的步骤，抓"大概意思"；本次只是**先归纳**，再继续讨论变动与论证，逐步推进。

## 四、缺口（本次要补的）

- **G1** 二级条目只"字头+一句话"，**没把"经验/复用命令/坑"绑到条目**——一个词带不出全部。
- **G2** 容器（Docker）未进检字表。
- **G3** 复用层未显式成类、**"上提门槛"未写进规则**，谁复用谁去重没约定。
- **G4** "每个资产：用它能干什么 / 成功过什么"没有统一字段/聚合。

## 五、备选方案（待主人裁决）

- **D1 二级条目怎么聚合经验/坑？**
  - 方案 A（省）：给 `经验库`/`踩坑总表`每条打 `@检索词@`，`wk-find <词>` 一次带出「资产 + 复用命令 + 经验 + 坑」。**不新建副本，零漂移**。
  - 方案 B（重）：每个重要条目建独立"条目页"（项目已是此模式，但资产类数量大，成本高）。
  - 倾向：A 为主，仅对"大项目"用 B（`projects/` 已在做）。
- **D2 复用"上提门槛"定多少？** 倾向：同一逻辑重复 ≥3 处 或 属"出口型/取数型"能力 → 上提为共享函数/单一入口；上提必带**注释 + 检索词 + 台账登记**；"没注释/没检索词/没登记 = 查不到 = 没复用"。
- **D3 调用 vs 重写？** 倾向：**调用优先**；动手前先 `wk-find`；例外（场景特殊、复用带耦合/副作用，如 `radarr-relay.py`"独立勿动"）才局部自写并注明原因。
- **D4 容器类**：并入 `wk-find`（数据源 `Docker容器与存储.md`）。
- **D5 是否给台账加"用途/成功案例"必填字段**：加字段 = 维护成本，需权衡。

## 七、已定修正（2026-10-17 主人补充，P4/P6）

**P4·`scratch/` 兜底（已写入 scratch/README + 规则库）**
1. 存活期 **30 天**：新进文件**从进入 `scratch/` 那天起算**（不按文件 mtime）。
2. **存量文件豁免**：规则上线前已在 `scratch/` 的**不自动清**，只出清单人工审。
3. 被引 ≥1 次 → 续期；=0 → 到期候选；**连续两轮（≈两个月）=0 才清**。
4. 30 天起算点 = **机制上线日**；**首次扫描只出清单、不删**；存量先豁免，攒够引用记录再开考核。

**P6·被引次数（只做脚本层，分层考核）**
- 静态扫描（grep 引用）→ 输出到 `wk-find` 加「被引次数」字段。
- 扫描范围**只限未提纯层**（`scratch/`、临时脚本区、散落脚本）。
- **豁免层**：`tools/`、`/usr/local/bin`、`wk.sh`、`qq-send.sh` 及所有已登记为砖/墙的，不参与「=0 就清」。
- 判据分层：未提纯层 =0 且 30 天没动 → 清；砖层永不自动清、只展示引用次数；墙/房不考核。

**P11·D1–D5 落地口径**

- D2 上提门槛：≥3 处 / 出口取数型 / 易错涉权限。
- D3 调用 vs 重写：token 对比 —— **读接口+调用比重写贵才重写**。
- D4 容器并入检字表（见 P10）。
- D5 高频台账加「用途/成功案例」字段（通知、容器、复用脚本 三类）。
