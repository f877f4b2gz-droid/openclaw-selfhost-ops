## 二、工作区关系（唯一真相源原则）

- **NAS `workspace/` + `docs/` = 唯一长期事实源；悟空 = 唯一写入者。**
- 八戒**只读**共享源，**不得**在 PC 另写"PC 版 workspace 文档"（= 两份真相必然漂移）。
- 八戒在 PC 的**发现/结论/踩坑** → **回报悟空**，由悟空写入 NAS 文档。
- 稳定物理事实（机器角色/IP/硬件/固件包）→ NAS 共享；易变上下文（当前任务/会话）→ 各自 `MEMORY.md`；机密（token/口令）**只传位置，不传密文**。
- 认领任务先核版本：`sha256sum <OPENCLAW_PATH>`，变了就重读。

## 三、八戒脚本 / 临时代码的归宿（本次要补的缺口）

**现状实测（2026-10-16）**：PC `default-workspace` = **5005 文件 / 462 目录 / 187MB**，大量一次性脚本与产物（`.py` 1555、`.pyc` 1295、`.sh` 407、`.png` 606、`.log` 100…），命名多为 `apply_*.sh` `a16.py` `audit1/2.sh` 这类流水号。**NAS 侧零副本，未落盘。**

**归宿规则（建议，待主人定）**：

1. **一次性脚本 / 临时产物** → **留在 PC**，不往 NAS 搬（避免污染唯一真相源）。但 PC 侧要**归目录 + 加注释头**：`scripts/`（脚本）｜`tmp/`（临时）｜`logs/`（日志）｜`assets/`（截图/固件包）。
2. **有复用价值的脚本 / 命令** → **回报悟空**，由悟空**上提为共享资产**（NAS `/usr/local/bin` 脚本 或 `wk.sh` 函数），**登记台账 + 打检索词**。判据：同一逻辑重复 ≥3 处，或属"出口/取数型"能力。（呼应总纲复用体系 → `docs/总纲与复用体系_设计草案.md` §D2）
3. **结论 / 事实 / 踩坑** → 回报悟空写入 NAS `docs/`（踩坑进 `踩坑总表.md`、经验进 `经验库.md`）。
4. **命名**：禁 `a16.py` `audit1.sh` 这类流水号；用**语义名**（中文自解释优先）。
5. **定期清理**：`.pyc` / 过期日志 / 一次性截图不囤（PC 侧自理，参照 NAS `清理策略总表.md` 精神）。

> 一句话：**PC 是操作台，随便造；有复用价值的结晶，回报悟空上提到 NAS。**

## 四、规则交底（八戒必读）

**红线**：不外传敏感信息；不把 NAS 机密抄到 PC；公网不暴露服务；不 root 直登（手机/系统用规定账号）；不 kill 系统原生应用；**不把备份口令写进聊天/命令行**。
**行为**：一律简体中文；只给结果不啰嗦、不复述、不道歉；一次办结；做不到直说；失败必上报不吞错；动手前先备份（`.bak.YYYYMMDD-HHMMSS`）。
**省 token／反死循环**（本次新增，八戒同样适用）：索引命中后**用本地命令（grep/head）读片段**，禁把整文件/整仓/整页塞进上下文；同一手段连续失败/无进展 **≥2~3 次 → 停**，先列「绕过／跳过／替代」候选（≥2 个）再选，**禁无脑重复**，卡住必上报。
**交付归属**：每次交付显式声明，如 `【执行：八戒(PC)｜编排：悟空(NAS)】`。
**分歧**：以原始证据（源码/串口日志/实测）为准，禁 Agent 互相说服；改一处（NAS docs），另一侧重新读。
